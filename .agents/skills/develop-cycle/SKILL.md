# Навык: Автономный цикл разработки (Develop Cycle)

Используй этот навык при выполнении задач разработки по дорожной карте `TODO.md` или при указании пользователя следовать циклу разработки.

## Пошаговый алгоритм выполнения задачи

### Шаг 1: Выбор задачи
1. Открой `TODO.md` и `docs/NEXT_STEPS.md`.
2. Выбери один логически следующий незавершенный пункт со статусом `[ ]`.
3. Если пункт слишком объемный — декомпозируй его прямо в плане на 2–3 небольших проверяемых подпункта.

### Шаг 2: Анализ и реализация
1. Проанализируй существующий код в `src/` и связанные архитектурные решения в `docs/DECISIONS.md`.
2. Проверь: не требуется ли согласование через **Архитектурный шлюз Романа** (`ARCHITECT DECISION REQUIRED`).
3. Реализуй изменение простым, надежным и типизированным кодом без дублирования.

### Шаг 3: Верификация кода
1. Выполни сборку и проверку типов: `npm run build` (`tsc && vite build`).
2. При наличии ошибок немедленно исправь их и повтори сборку.

### Шаг 4: Обновление документации (DoD)
1. Обнови `TODO.md` (поставь шагу статус `[~]`).
2. Обнови `docs/PROJECT_STATE.md`, если добавилась новая возможность или изменилось поведение.
3. Внеси запись в `docs/CHANGELOG.md` в секцию текущей версии с описанием изменений.
4. Если принято техническое соглашение — внеси запись в `docs/DECISIONS.md`.

### Шаг 5: Запуск независимого аудитора
Вызови отдельного субагента через инструмент `invoke_subagent`:
- **TypeName:** `self` (или кастомный субагент, объявленный через `define_subagent`)
- **Role:** `Development Auditor`
- **Prompt:**
  ```text
  Проведи независимый аудит выполненного шага разработки МКонструктора по правилам из файла .agents/skills/develop-cycle/references/auditor_prompt.md.
  
  Проверяемый шаг: <название шага из TODO.md>
  Измененные файлы: <список файлов>
  Результат сборки (npm run build): <успешно/ошибки>
  
  Самостоятельно прочитай измененные файлы, проверь отсутствие регрессий, дублей кода и актуальность документации.
  Дай вердикт в формате AUDIT RESULT: PASS или AUDIT RESULT: FAIL.
  ```

### Шаг 6: Обработка вердикта аудита
- **Если AUDIT: PASS:**
  - Переведи статус в `TODO.md` из `[~]` в `[x]`.
  - Зафиксируй успешное завершение шага.
  - Переходи к следующему шагу или доложи пользователю о завершении.
- **Если AUDIT: FAIL:**
  - Внимательно изучи замечания аудитора.
  - Исправь недочеты в коде или документации.
  - Повтори `npm run build`.
  - Запусти повторный аудит (максимум 2 круга аудита).
  - При повторном `FAIL` остановись и запроси помощь Романа (`AUDIT DEADLOCK: ARCHITECT REVIEW NEEDED`).
