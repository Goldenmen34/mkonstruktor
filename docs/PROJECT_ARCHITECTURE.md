# Архитектура Платформы МебельPlaner24

## 1. Концепция и Главные Принципы

**МебельPlaner24** — это коммерческая инженерная веб-платформа для проектирования, визуализации и расчета стоимости корпусной мебели (кухни, шкафы, гардеробные).

### Главный архитектурный закон:
> **3D-сцена — это лишь визуальное представление (View) данных, а не сам источник данных.**

Вся мебель в системе существует в виде строгой иерархической модели данных (Domain Model), полностью независимой от Three.js, WebGL или используемого UI-фреймворка.

---

## 2. Модель Данных (Domain Data Hierarchy)

```
Мебельный Проект (Project) [версионируемый JSON]
 ├── Метаданные (Клиент, дата, дилер, лицензия)
 ├── Помещение (Room)
 │    ├── Стены (Walls) [2D-координаты, толщина, высота]
 │    ├── Проёмы (Openings) [Окна, двери, ниши]
 │    ├── Точки коммуникаций (Utilities) [Розетки, вода, газ, вентканал]
 │    └── Отделка (Finishes) [Материалы пола, стен, потолка]
 └── Мебельные Модули (Furniture Modules)
      ├── Идентификатор (UUID), Категория (Kitchen/Wardrobe), Подтип
      ├── Габаритные параметры (W, H, D в мм), Позиция (X, Y, Z), Угол поворота
      ├── Секции и наполнение (Sections)
      └── Спецификация деталей (Parts Breakdown)
           ├── Деталь (Part) [Боковина левая, Дно, Полка, Фасад и т.д.]
           │    ├── Размеры (Ш × В × Т в мм)
           │    ├── Материал плиты (Material ID: ЛДСП 16мм, МДФ 19мм)
           │    ├── Кромка (Edge Banding) [Кромка 0.4 / 1.0 / 2.0 мм по сторонам]
           │    └── Присадка / Пазы (Machining) [будущий задел под ЧПУ]
           └── Фурнитура (Hardware)
                ├── Петли, направляющие ящиков, подъемники
                ├── Ручки, опоры (ножки), навесы
                └── Расходные материалы (стяжки, конфирматы)
```

## 3. Слои Системы (Layered Architecture)

```
┌─────────────────────────────────────────────────────────────┐
│                       UI СЛОЙ (React)                       │
│    Шапка, Боковая панель каталога, Инспектор параметров,    │
│            Модальные окна лицензий, Панель сметы            │
└──────────────────────────────┬──────────────────────────────┘
                               │ (Вызовы actions / Селекторы)
┌──────────────────────────────▼──────────────────────────────┐
│             СЛОЙ СОСТОЯНИЯ (Zustand Stores)                 │
│      usePlannerStore, useLicenseStore, useRoomStore         │
└──────────────────────────────┬──────────────────────────────┘
                               │
       ┌───────────────────────┴───────────────────────┐
       ▼                                               ▼
┌──────────────────────────────┐     ┌──────────────────────────────┐
│       ДОМЕННЫЙ СЛОЙ          │     │        3D-СЛОЙ (VIEW)        │
│   (Чистая бизнес-логика):    │     │          (Three.js):         │
│  - Параметрические правила   │     │  - SceneManager              │
│  - Валидация размеров        │────►│  - ModuleBuilder             │
│  - Расчет сметы (BOM)        │     │  - PBR Материалы / Шейдеры   │
│  - Привязки и коллизии       │     │  - Камера / Студийный свет   │
│  - Сериализация / Миграции   │     │  - Raycast Colliders         │
└──────────────────────────────┘     └──────────────────────────────┘
```

1. **Доменный слой (Domain Layer):**
   * Написан на чистом TypeScript.
   * Не содержит ссылок на `THREE.*`, DOM-элементы или React-хуки.
   * Полностью тестируем через автоматические unit-тесты.
   * Отвечает за проверку правил (например: «минимальная ширина тумбы с 2 дверьми — 600 мм», «вытяжка должна быть выше варочной на 650 мм»).

2. **3D-Слой представления (Presentation Layer):**
   * Получает на вход чистые данные `FurnitureModule` и строит оптимизированную иерархию мешей Three.js.
   * Реализует CAD-визуализацию: мягкие тени, контуры ребер (`EdgesGeometry`), размерные плашки, анимацию фасадов.
   * Оснащен изолированными габаритными коллайдерами (`raycast_collider`) для 100% точного выбора модулей курсором.

3. **Слой состояния (State Management):**
   * Хранит снимок проекта в нормализованном виде.
   * Поддерживает историю действий (Undo / Redo).

4. **Слой безопасности и SaaS:**
   * Проверка лицензий и токенов доступа.
   * Ограничения демо-доступа.
   * Готовность к серверной валидации и обфускации.

---

## 4. Требования к производительности 3D

1. **Контроль Draw Calls:** Повторное использование материалов через кэш (`materialsCache`).
2. **Изоляция Raycasting:** Луч мыши никогда не опрашивает тысячи мелких полигонов фурнитуры или контурные линии — проверка происходит только по простым bounding-боксам модулей.
3. **Очистка ресурсов (Disposal):** При удалении или перестроении модуля все геометрии и материалы корректно освобождаются из памяти видеокарты (`geometry.dispose()`, `material.dispose()`).

---

## 5. Долгосрочная масштабируемость

* **Поддержка кастомных фабричных баз:** Модули описываются в декларативном JSON-формате, что позволит фабрикам загружать свои каталоги без изменения кода платформы.
* **Экспорт на производство:** Наличие детальной спецификации (деталировка в мм + кромка) закладывает прямой мост для будущей генерации файлов раскроя и карт присадки (DXF / CSV / Базис-Мебельщик).
